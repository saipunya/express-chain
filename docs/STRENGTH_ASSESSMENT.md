# ระบบประเมินและพัฒนาความเข้มแข็ง รุ่นแรก

หน้าสาธารณะ: `/strength/assessments/public` ไม่ต้องเข้าสู่ระบบ หรือกด “ประเมินความเข้มแข็ง” จากเมนู / “ประเมินด้วยตนเอง” ในหน้าแรก

เจ้าหน้าที่จัดการรายการที่บันทึก: `/strength/assessments` ผ่านแดชบอร์ด ผู้ไม่เข้าสู่ระบบที่เปิดลิงก์นี้จะถูกพาไปหน้าสาธารณะ

## ขอบเขต

- ปีประเมิน 2569 แยกสหกรณ์ภาคเกษตร นอกภาคเกษตร และกลุ่มเกษตรกร โดยเลือกประเภทจากทะเบียนฝั่งเซิร์ฟเวอร์
- คำนวณมิติ 1 และ 4 จากข้อเท็จจริง มิติ 2 เลือกคำนวณจากข้อมูลทางการเงิน 6 อัตราส่วน มิติ 3 ให้คะแนนการจัดการองค์กรแยกองค์ประกอบ ทั้งสองมิติยังเลือกใช้คะแนนรวมต้นทางพร้อมหลักฐานได้
- แสดงคะแนนรายข้อ รายมิติ คะแนนรวม เงื่อนไขที่ไม่ผ่าน และคำแนะนำพร้อมที่มา
- ร่างข้อมูลที่ยังไม่ครบได้ แยกข้อมูลขาดหายออกจากศูนย์ และแยกสถาบันที่ไม่เข้าเป้าหมายออกจากชั้น 3
- เพิ่มแผนพัฒนาได้ 8 งาน พร้อมผู้รับผิดชอบ กำหนดเสร็จ สถานะ และหลักฐานผลสำเร็จ
- เก็บ snapshot ทะเบียน ข้อมูลประเมิน รุ่นเกณฑ์ แผน และผลคำนวณทุกครั้งที่บันทึก
- เจ้าหน้าที่ที่เข้าสู่ระบบดูรายการที่บันทึกได้ ผู้สร้างรายการเท่านั้นที่แก้ไขได้ หน้าสาธารณะเปิดให้ทุกคนรวมถึงบัญชีสถาบันประเมินตนเอง โดยไม่เข้าถึงรายการเจ้าหน้าที่

ผลเป็น **การประเมินเบื้องต้น**: คะแนนอ้างอิงคู่มือ 2569 ส่วนเงื่อนไขการจัดชั้นอ้างอิงภาพปี 2568 และใช้ค่าเฉลี่ยมิติ 2 กลุ่มเกษตรกร 15 ตามภาพดังกล่าว ไม่มีการรับรองผลอย่างเป็นทางการหรือเขียนผลทับ `tbl_strength` / `new_strength`

## วิธีใช้

1. เลือกสถาบันจากทะเบียน ตรวจรอบบัญชีและการอยู่ในขอบเขตการประเมิน
2. กรอกข้อมูลมิติ 1/4 มิติ 2 กรอกจำนวนเงินเป็นบาท มิติ 3 เลือกให้คะแนนแยกองค์ประกอบและรูปแบบมาตรฐาน/ภาพรวม พร้อมระบุหลักฐาน
3. กด “ประเมินผลและดูคำแนะนำส่งเสริม” เพื่อเปิดหน้าผลแยกจากแบบกรอก ระบบแสดงคะแนน เงื่อนไขที่ยังไม่ผ่าน และคำแนะนำตามข้อมูลที่กรอก โดยยังไม่บันทึก
4. ตรวจข้อที่ยังไม่ผ่านและคำแนะนำส่งเสริม พร้อมหลักฐานที่ต้องติดตาม หากข้อมูลคลาดเคลื่อนให้กลับไปแก้แล้วประเมินใหม่
5. ในหน้าผล เลือก “กลับไปแก้ข้อมูล” หรือ “บันทึกผลประเมิน” แล้วกลับมาอัปเดตผ่าน “ปรับข้อมูล / ติดตามแผน” ได้ ข้อมูลไม่ครบสามารถ “บันทึกฉบับร่าง”

ทุกวันที่ในช่องกรอกใช้ ค.ศ. รอบบัญชีที่รองรับสิ้นสุดในช่วง 2025-04-01 ถึง 2026-03-31 วันรับตรวจและวันประชุมใช้ข้อมูลถึง 2026-08-31 แผนพัฒนาสามารถกำหนดวันในอนาคตได้ การทำแผนเสร็จไม่เพิ่มคะแนนอัตโนมัติ

กรณีมีข้อยกเว้น, ตัวชี้วัด 1.2 กลุ่มเกษตรกรจ่ายเฉพาะปีก่อน, หรือกลุ่มเกษตรกรส่งงบหลัง 90 วัน จะขึ้นรอตรวจสอบและไม่สรุปชั้น ดูข้อค้นพบจากเอกสารใน `docs/strength-assessment-feasibility-2569.md`

## การจัดเก็บและติดตั้ง

ใช้ Express/EJS/MySQL และ dependencies เดิม ไม่ต้องเพิ่มแพ็กเกจ โมดูลถูก mount ที่ `/strength/assessments` ก่อน route `/:code` ใน `routes/strengthRoutes.js`

ตารางใหม่ถูกสร้างแบบ `CREATE TABLE IF NOT EXISTS` เมื่อมีการเปิดรายการหรือบันทึกครั้งแรก:

- `strength_assessments`: รายการปัจจุบัน หนึ่งสถาบันต่อปีประเมิน
- `strength_assessment_revisions`: snapshot แต่ละฉบับเพื่อประวัติย้อนหลัง

บัญชีฐานข้อมูลของแอปต้องมีสิทธิ์ CREATE TABLE, SELECT, INSERT, UPDATE สำหรับตารางใหม่ ไม่มีการแก้ schema ของตารางเดิม การเขียนรายการและประวัติอยู่ใน transaction เดียวกัน และมีเลขฉบับป้องกันการเขียนทับจากฟอร์มเก่า

รีสตาร์ทแอปตามวิธีใช้งานเดิมหลังนำโค้ดขึ้นระบบ การทดสอบระหว่างพัฒนาใช้ข้อมูลจำลอง ไม่ได้สร้างตารางหรือเขียนข้อมูลในฐานข้อมูลจริง

## ข้อจำกัดที่ระบุในหน้าจอ

- ยังไม่เชื่อม API ส่วนกลาง และยังไม่อ่านงบ PDF/ภาพอัตโนมัติ ผู้ใช้กรอกข้อมูลจากงบและทะเบียนประกอบ
- ช่องหลักฐานเป็นข้อความอ้างอิง/ที่อยู่เอกสาร ยังไม่มีการอัปโหลดหรืออ่านเอกสารด้วย AI ในโมดูลนี้
- ประเภทสถาบันที่ไม่ชัดเจนต้องตรวจทะเบียนก่อน ไม่เดาประเภทให้เอง
- ไม่มีผลรับรองเกณฑ์ปี 2569 จนกว่าได้รับคำยืนยันเงื่อนไขจัดชั้นและแก้จุดกำกวมของคู่มือ
- รุ่นแรกมีปีประเมินเดียว ไม่มี workflow ผู้ตรวจรับรองหรืออุทธรณ์
- ประวัติแสดงผู้บันทึกและเวลา 30 ฉบับล่าสุด ส่วน snapshot ทุกฉบับเก็บในฐานข้อมูล

## การตรวจสอบ

`npm test` รวม unit tests สูตรและกรณีขอบ, HTTP integration ด้วย store จำลอง, และการทดสอบ transaction/rollback ด้วยฐานข้อมูลจำลอง ไม่มีการเรียกฐานข้อมูลจริงในชุดทดสอบใหม่

กรณีหลัก: คะแนน 55/65/80/85, คะแนนสูงแต่ติดเงื่อนไข, ข้อมูลไม่ครบ, ไม่เข้าเป้าหมาย, หลักฐานขาด, วันส่งงบ 30/60/90 วัน, ประชุมวันที่ 150/151, ข้อยกเว้น, ประเภทสถาบัน, ตัวเลข/วันที่ผิด, CSRF, การหนี HTML, สิทธิ์แก้ไข และการเขียนทับฉบับเก่า

ตรวจหน้ารายการและผลด้วย Playwright บน localhost ที่ใช้ข้อมูลจำลอง แยกจากเซิร์ฟเวอร์จริง

## การคำนวณมิติที่ 2 จากข้อมูลทางการเงิน

รุ่นเกณฑ์ `2569-manual-v2-financial_2568-classification-provisional` ใช้คู่มือหน้า 16–23 สำหรับสหกรณ์ และหน้า 46–52 สำหรับกลุ่มเกษตรกร ตารางเกณฑ์แยกการเกษตร นิคม ประมง ออมทรัพย์ เครดิตยูเนี่ยน ร้านค้า บริการ และกลุ่มเกษตรกร

| ตัวชี้วัด | สูตร | น้ำหนัก |
| --- | --- | --- |
| 2.1 หนี้สินต่อทุน | หนี้สินทั้งสิ้น / ทุน | 3 |
| 2.2 ทุนสำรองต่อสินทรัพย์ | ทุนสำรอง / สินทรัพย์ทั้งสิ้น | 2 |
| 2.3 ผลตอบแทนต่อสินทรัพย์ | กำไรจากการดำเนินงาน / สินทรัพย์ถัวเฉลี่ย × 100 | 4 |
| 2.4 ค่าใช้จ่ายดำเนินงานต่อกำไรก่อนหักค่าใช้จ่ายดำเนินงาน | ค่าใช้จ่ายดำเนินงาน / กำไรก่อนหักค่าใช้จ่ายดำเนินงาน × 100 | 4 |
| 2.5 ทุนหมุนเวียน | สินทรัพย์หมุนเวียน / หนี้สินหมุนเวียน | 3 หรือ 7 |
| 2.6 ลูกหนี้ระยะสั้นชำระตามกำหนด | ต้นเงินที่ชำระตามกำหนด / ต้นเงินถึงกำหนด × 100 | 4 หรือไม่คิดคะแนน |

สินทรัพย์ถัวเฉลี่ย = (สินทรัพย์ปีปัจจุบัน + ปีก่อน) / 2 สำหรับสหกรณ์ที่ส่งหักรายเดือน เลือกสูตร 2.6 เป็น (ลูกหนี้ทั้งหมด − NPLs) / ลูกหนี้ทั้งหมด × 100 ได้ตามคู่มือหน้า 21

- กรอกเงินเป็นบาท ทศนิยมไม่เกิน 2 ตำแหน่ง สูงสุด 1 ล้านล้านบาท เก็บจำนวนเงินเป็นข้อความและคำนวณหน่วยสตางค์ด้วย BigInt เพื่อไม่ให้ค่าตรงขอบเกณฑ์คลาดเคลื่อนจาก floating point
- แสดงอัตราส่วน 4 ตำแหน่ง (ปัดเศษ) แต่เทียบเกณฑ์ด้วยค่าจริงตัดเศษเหลือ 2 ตำแหน่ง ไม่ใช้ค่าที่ปัดแล้ว
- คะแนนแต่ละข้อ = ระดับ 0/1/2/3 หาร 3 คูณน้ำหนัก ระบบรวมค่าถ่วงน้ำหนักเต็มก่อนปัดผลมิติเป็น 2 ตำแหน่ง คะแนนรายข้อที่แสดงปัดแยกกัน จึงอาจรวมต่างจากคะแนนมิติ 0.01 คะแนน ตัวอย่างทุกข้อระดับ 2 ได้มิติ 2 เท่ากับ 13.33
- ทุนเป็นศูนย์/ติดลบ, ทุนสำรองศูนย์, กำไรจากการดำเนินงานไม่เป็นบวก และกำไรก่อนหักค่าใช้จ่ายไม่เป็นบวก ใช้ 0 คะแนนในข้อที่คู่มือกำหนด หนี้สินหมุนเวียนศูนย์ให้ข้อ 2.5 ขั้นสูง
- เมื่อไม่มีลูกหนี้ระยะสั้นถึงกำหนด และมีข้อมูลปริมาณธุรกิจเงินให้กู้ ย้ายน้ำหนัก 4 จากข้อ 2.6 ไปข้อ 2.5 เป็น 7 คะแนน ข้อมูลว่างไม่เท่ากับศูนย์ และไม่ใช้เป็นเหตุย้ายน้ำหนัก
- กรณีแบบส่งหักรายเดือนลูกหนี้ทั้งหมดเป็นศูนย์ หรือเป็น NPLs ทั้งหมด ให้รอตรวจสอบเงื่อนไขกับผู้ประเมิน ไม่เดาคะแนนจากตัวหารศูนย์หรือเงื่อนไขที่ไม่ชัดเจน
- งบไม่สมดุล, กำไรไม่สัมพันธ์กับค่าใช้จ่าย, ค่าใช้จ่ายติดลบ หรือตัวหารสินทรัพย์เป็นศูนย์ที่คำนวณไม่ได้ จะรอตรวจสอบก่อนจัดชั้น แม้คำนวณบางอัตราส่วนได้
- ใช้ประเภทจากทะเบียนที่บันทึกไว้กับรายการ ตรวจซ้ำฝั่งเซิร์ฟเวอร์ หากทะเบียนไม่ระบุประเภทย่อย ผู้กรอกเลือกได้เฉพาะประเภทในกลุ่มเดียวกัน ต้องระบุหลักฐาน
- คำนวณเมื่อกด “คำนวณอัตราส่วนและดูผล” หรือ “คำนวณและดูคำแนะนำ” และคำนวณซ้ำฝั่งเซิร์ฟเวอร์เมื่อบันทึก ไม่รับคะแนนมิติ 2 ที่ส่งแทรกมาในโหมดคำนวณ
- รายการเดิมไม่มีโหมดคำนวณยังเปิดและแก้ไขด้วยคะแนนต้นทางได้ ไม่คำนวณย้อนหลังทับ snapshot เดิม การเปลี่ยนโหมดจะเก็บเฉพาะข้อมูลที่ใช้ในฉบับใหม่ ส่วนฉบับเดิมยังอยู่ในประวัติ

## มิติที่ 3 แยกคะแนนรายด้าน

รุ่นปัจจุบัน `2569-manual-v3-organization_2568-classification-provisional` เพิ่มการคำนวณมิติ 3 ตามคู่มือหน้า 24–28 / 53–57 โดยมีวิธีใช้งานดังนี้

1. เลือก “ให้คะแนนแยกตามองค์ประกอบ” และรูปแบบการประเมินที่ใช้จริง
2. แบบมาตรฐานเลือกกรอกระดับคุณภาพรายด้าน หรือคะแนนผลประเมินรายด้าน 0–100 (ไม่ใช่คะแนนถ่วงน้ำหนัก)
3. กด “คำนวณคะแนนมิติที่ 3” ตรวจคะแนนแต่ละด้าน คะแนนรวมและคำแนะนำ ก่อนบันทึก

| องค์ประกอบ | สหกรณ์ | กลุ่มเกษตรกร |
| --- | --- | --- |
| เทคโนโลยีบัญชี | 3.1 เต็ม 4 | ไม่ประเมินข้อนี้ |
| สภาพแวดล้อมการควบคุม | 3.2 เต็ม 4 | 3.1 เต็ม 5 |
| ความเสี่ยงและกิจกรรมควบคุม | 3.3 เต็ม 4 | 3.2 เต็ม 5 |
| ระบบข้อมูลสารสนเทศและการสื่อสาร | 3.4 เต็ม 4 | 3.3 เต็ม 5 |
| ระบบการติดตามและประเมินผล | 3.5 เต็ม 4 | 3.4 เต็ม 5 |

เกณฑ์รายด้านมาตรฐาน: ดีมาก (> 95) = ระดับ 3, ดี (> 80–95) = ระดับ 2, พอใช้ (> 60–80) = ระดับ 1, ต้องปรับปรุง (≤ 60) / ไม่มีการควบคุมภายใน = ระดับ 0 ใช้ระดับหาร 3 คูณน้ำหนัก โดยไม่ตัดเศษคะแนนดิบตามกฎอัตราส่วนของมิติ 2

เทคโนโลยีบัญชีใช้คะแนนตรง: จัดทำบัญชีด้วยโปรแกรมครบทุกธุรกิจ 4 คะแนน บางส่วน 2 คะแนน ไม่ใช้ 0 คะแนน ใช้ทั้งแบบมาตรฐานและภาพรวมสำหรับสหกรณ์

แบบภาพรวมเลือกผลคุณภาพเพียงหนึ่งค่า ดีมาก/ดี/พอใช้/ต้องปรับปรุงหรือไม่มีการควบคุมภายใน แล้วถ่วงน้ำหนัก 16 คะแนนสำหรับสหกรณ์ หรือ 20 คะแนนสำหรับกลุ่มเกษตรกร ไม่ดึงรายด้านมาตรฐานที่ซ่อนไว้มารวม และไม่เฉลี่ยคะแนนรายด้านแทนผลภาพรวม

รวมค่าถ่วงน้ำหนักเต็มก่อนปัดผลมิติเป็น 2 ตำแหน่ง เช่น กลุ่มเกษตรกรทุกด้านระดับ 2 ได้ 13.33 คะแนน สหกรณ์ทุกด้านระดับ 2 และใช้เทคโนโลยีบัญชีเต็มระบบได้ 14.67 คะแนน คะแนนแต่ละด้านในตารางปัดแยกกันจึงอาจรวมต่าง 0.01 คะแนน

ข้อมูลรายด้านไม่ครบยังบันทึกร่างได้ แต่ไม่สรุปชั้น ไม่ใช้ศูนย์แทนช่องว่าง เก็บข้อมูลรายด้าน สูตร ระดับและคะแนนไว้ใน snapshot และไม่รับคะแนนรวมที่แทรกมาจากแบบฟอร์มในโหมดคำนวณ รายการเก่าที่มีเฉพาะคะแนนรวมยังเปิด/แก้ไขเป็นโหมดต้นทางได้ หากต้องการแยกรายด้านให้เปลี่ยนวิธีให้คะแนนและกรอกผลจริง ไม่กระจายคะแนนรวมเก่าเป็นคะแนนรายด้านอัตโนมัติ

ยังใช้ผลประเมินและหลักฐานรายด้านจากผู้ประเมิน ไม่ได้แทนแบบตรวจประเมินกิจกรรมย่อยทุกข้อในคู่มือ

## ขั้นตอนสำหรับผู้กรอกและคำแนะนำส่งเสริม

รุ่น `2569-manual-v4-promotion_2568-classification-provisional` เพิ่มปุ่ม “กรอกข้อมูลประเมินความเข้มแข็ง” ในแดชบอร์ดสำหรับเจ้าหน้าที่ทุกบัญชี จากเดิมที่ปุ่มนี้อยู่เฉพาะส่วนผู้ดูแลระบบ สิทธิ์ดูและแก้ไขรายการเจ้าหน้าที่ยังใช้ตามขอบเขตเดิม ส่วนการประเมินสาธารณะใช้เส้นทางแยกด้านล่าง

ผู้ใช้เลือกสถาบัน กรอกข้อมูลจริงทั้ง 4 มิติ และเปิดหน้าผลพร้อมคำแนะนำได้ก่อนบันทึก หน้าผลเก็บข้อมูลและแผนที่กรอกไว้สำหรับย้อนแก้ไข ไม่เก็บไว้ใน localStorage เมื่อบันทึกจะตรวจข้อมูล สิทธิ์ CSRF และเลขฉบับอีกครั้ง พร้อมคำนวณใหม่ฝั่งเซิร์ฟเวอร์ ไม่รับคะแนนรวมหรือชั้นที่แทรกมาจากผู้ใช้

คำแนะนำแยกเป็นข้อมูลที่ต้องตรวจ เงื่อนไขที่ยังไม่ผ่าน และโอกาสเพิ่มประสิทธิภาพ คะแนนรายข้อที่ยังไม่เต็มไม่ได้ถูกเรียกว่าตกมาตรฐานโดยอัตโนมัติ ข้อที่ไม่ผ่านใช้เงื่อนไขพื้นฐานและเป้าหมายชั้นอ้างอิงตามรุ่นเกณฑ์ พร้อมหลักฐานติดตามและที่มา กรณีข้อมูลไม่ครบหรือมีข้อยกเว้นจะแสดงว่ายังสรุปไม่ได้

แผนส่งเสริมเป็นส่วนเพิ่มเติมที่เปิดภายหลังได้ โดยไม่ต้องกรอกแผนก่อนคำนวณผล ในหน้าปรับข้อมูลสามารถกดคำนวณรายมิติเพื่อแสดงคำแนะนำและเลือก “เพิ่มลงแผนพัฒนา” ได้

## ประเมินสาธารณะโดยไม่เข้าสู่ระบบ

- เปิด `/strength/assessments/public` เลือกประเภทสถาบันและกรอกชื่อได้ตามต้องการ (ชื่อไม่บังคับ) จากนั้นกรอกข้อมูลทั้ง 4 มิติ ใช้สูตรและคำแนะนำชุดเดียวกับส่วนเจ้าหน้าที่
- หน้าผลสามารถย้อนแก้ข้อมูล คำนวณใหม่ หรือกด “พิมพ์ผล / บันทึก PDF” โดยเลือกเครื่องพิมพ์หรือ Save as PDF ในเบราว์เซอร์
- ไม่อ่านทะเบียนสถาบันหรือรายการประเมินเจ้าหน้าที่ และไม่บันทึกคำตอบ/ผลลงฐานข้อมูล ไม่เก็บคำตอบใน session หรือ localStorage เมื่อปิดหน้าแล้วให้เริ่มกรอกใหม่
- ใช้ anonymous session เฉพาะ CSRF token เพื่อให้แบบกรอกและการคำนวณผูกกับเบราว์เซอร์ที่เปิด ไม่จำเป็นต้องสมัครบัญชี
- ไม่มี action บันทึกและไม่มีรายการผลย้อนหลังในเส้นทางสาธารณะ การเรียก `/public/:id` หรือ `/public/:id/edit` ได้ 404 เส้นทางเจ้าหน้าที่ยังคงตรวจ login, สิทธิ์และผู้สร้างรายการ
- ผู้ใช้ที่เข้าสู่ระบบเป็นบัญชีสถาบันเข้าหน้าสาธารณะได้เช่นเดียวกับผู้ไม่เข้าสู่ระบบ แต่ไม่สามารถใช้เส้นทางนี้เข้าถึงข้อมูลเจ้าหน้าที่
- คำตอบส่งด้วย POST พร้อม `Cache-Control: no-store` และแสดงข้อความด้วย EJS escaping รวมถึงข้อมูลที่ส่งกลับไปแก้ไข ผลยังเป็นการประเมินด้วยตนเองเบื้องต้นตามเงื่อนไขอ้างอิงเดิม

ทดสอบการเข้าถึงสาธารณะด้วย store ที่ทำให้การเรียกฐานข้อมูลทุกชนิดล้มเหลว เพื่อยืนยันว่า start/evaluate/revise ไม่มีการอ่านหรือเขียนข้อมูลประเมินเดิม
